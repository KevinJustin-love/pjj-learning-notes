# GR-1：用未来图像预测训练一个会行动的 GPT

核实日期：2026-09-25。**Unleashing Large-Scale Video Generative Pre-training for Visual Robot Manipulation**，Hongtao Wu、Ya Jing 等；[arXiv:2312.13139v2](https://arxiv.org/abs/2312.13139v2)，2023-12-21 版本，[官方仓库](https://github.com/bytedance/GR-1)标注 ICLR 2024。已读正文、附录和本地 PDF/TeX；以下均为作者报告，**未复现**。

## 1. 定位与影响证据

GR-1 的贡献是把“互联网人类视频预训练”和“机器人动作学习”放入同一个 Transformer：预训练预测未来画面，机器人微调同时预测画面与动作。论文称 GPT-style visual manipulation model；本调研将其归为联合视频—动作学习的前身/邻近路线，不因带视频分支就追认其自称 WAM。

直接的延续证据来自 [GR-2 §1](https://arxiv.org/abs/2410.06158v1)：作者明确称 GR-2 为 GR-1 的演进，并把 GR-1 作为真机和 CALVIN 对照。对新手而言，它是理解“视频辅助目标何以改善策略”的清晰起点，因为这里尚无视频扩散、动作扩散等额外采样机制。

## 2. 输入输出和 token 含义

§3.1 的任务为 `π(语言,历史图像,历史机器人状态) → 当前动作 + 未来图像`。机器人状态是末端六维位姿和二值夹爪；CALVIN 动作为三维位置增量、三维欧拉角增量及夹爪开闭。附录输入历史长度为 10，机器人微调预测 `t+3` 的图像；预测时间不是动作块长度。

| 模态 | 编码/输出 | 需要避免的误读 |
|---|---|---|
| 文本 | 冻结 CLIP 文本特征，每个时间步重复 | 不是语言模型逐词生成动作 |
| 图像 | 冻结 MAE 预训练 ViT；保留 CLS 全局特征，patch 经 Perceiver resampler 压缩 | 两个相机是真实多视角，不是两种图像编码器 |
| 状态 | 位姿、夹爪各线性映射并融合 | 输入状态与监督动作的绝对/增量语义不同 |
| `[ACT]` | 一个可学习的查询 embedding，经 MLP 输出连续臂动作和夹爪 logit | **查询 token 不是离散动作码** |
| `[OBS]` | 未来观察查询，经 Transformer decoder 重建图像 patch | 是预测分支，不是已知未来图像输入 |

官方 `models/gr1.py` 进一步核实：RGB 和手部 RGB 分开输入，shape 为 `B×T×3×H×W`；图像尺寸 224，重建 patch 为 `16×16×3`；动作输出为 `B×T×6` 和 `B×T×1`，部署读取当前步。参数值来自[官方实现](https://github.com/bytedance/GR-1/blob/main/models/gr1.py)，不代表所有后续 GR 系列都相同。

## 3. 最重要的机制：预测查询不能成为别人的条件

§3.2 把每一时刻的语言、状态、视觉表示和预测查询排成序列，再沿时间展开；加相对时间 embedding。骨干是 causal Transformer，但在常规因果 mask 之外，**所有 `[OBS]`、`[ACT]` 位置都不作为可被其他 token 读取的键值**。各查询可以读取此前真实条件，预测查询彼此不传递输出。

这意味着动作预测并不是先拿到一张生成图，再把生成图喂给逆动力学。动作头和图像头共享受训练的骨干特征；视频损失通过共享参数影响动作学习。将其解释为“动作直接注意预测帧、必须等像素生成完成”会把论文机制讲错。论文示意顺序为 `[OBS],[ACT]`，官方代码的序列为 `[ACT],[OBS],[OBS_HAND]`；由于查询均被屏蔽为 key/value，该顺序差异不应被误解为从图像预测向动作的直接信息流。

图像 decoder 用查询输出加带空间位置的 mask tokens，还原未来像素 patch；监督目标按 patch 归一化。动作 MLP 输出连续臂控制与夹爪。§3.2–3.3 明确：

`L预训练 = Lvideo(pixel MSE)`

`L微调 = Larm(Smooth-L1) + Lgripper(BCE) + Lvideo(pixel MSE)`。

因此它既不是 OpenVLA 的 action-token 交叉熵，也不是 π0/Fast-WAM 的连续流生成动作。训练图像可以直接提供未来监督；推理动作的因果输入只有实际观测历史。不能把训练期视频标签泄漏当作部署可用信息。

## 4. 数据与阶段

1. **视频预训练**（§3.3）：从 Ego4D 裁剪 3 秒的人类活动片段，得到 800k clips、8M frames。附录按 1/3 秒间隔抽帧，每步预测下一采样帧。Ego4D 原数据超过 3500 小时，不等于 GR-1 训练样本恰为 3500 小时。
2. **机器人微调**：仍冻结 CLIP 和 MAE，训练序列骨干、融合和输出头。CALVIN 全集为 24 小时无定向 play，GR-1 用带语言标注的约 1% 部分；HULC/MCIL 使用含无语言数据的全集，故横向表格不是严格等数据预算。
3. **低数据设置**：从 22,966 条语言标注训练轨迹中，每个任务取 66 条，共 2244 条，而非只训练 2244 个时间步（§4.1）。
4. **真机**：Kinova Gen2 七自由度臂，末端 RealSense 加固定 Kinect Azure；物体运输 1775 条演示，抽屉开关 2856 条（§4.2、附录）。

## 5. 如何理解 CALVIN 与真机结果

CALVIN 一次评测是一串最多 5 条指令：当前任务成功才下发下一条，超过 360 steps 则失败；评估 1000 条不同指令链。`Avg. Len.` 是平均连续完成任务数，范围 0–5；不能与 LIBERO 单任务成功率直接排名（附录 CALVIN Evaluation）。

| v2 表1 | 第1项成功率 | 完整5项成功率 | 平均链长 |
|---|---:|---:|---:|
| GR-1，ABCD→D | .949 | .731 | 4.21 |
| HULC，ABCD→D | .889 | .383 | 3.06 |
| GR-1，ABC→D 未见环境 | .854 | .401 | 3.06 |
| GR-1，10%语言轨迹 | .778 | .139 | 2.00 |
| GR-1，未见语言改写 | .764 | .196 | 2.17 |

摘要的 **94.9% 是第一项成功率，不能写成完整长任务成功率**。未见语言是用 GPT-4 为已有任务生成同义指令，不等于掌握新技能。ABC→D 测的是环境配色/物体布局变化，也不能直接称为任意相机位置泛化。

表2 真机结果为已见物体 .79、未见实例 .73、未见类别 .30、抽屉 .75。未见类别明显更弱：作者指出桃子与同色彩椒混淆、漏抓把手、关抽屉不完全等失败。这些分数属于不同小型任务集；本文所读正文/附录没有充分报告每个真机单元的试验数及方差，不能据此宣称统计显著或通用工业可靠性。

**受控消融比主表更能回答机制问题。** 附录表4 在 ABCD→D 中，无视频预训练且无视频预测的平均链长为 3.33；保留视频预测、从头训为 3.82；再加视频预训练为 4.21。ABC→D 对应 2.40/2.65/3.06，低数据对应 1.04/1.52/2.00。前两者隔离机器人阶段的视频辅助目标，后两者隔离视频预训练的增益；都不能单独证明增益来自几何一致性。附录表5 不使用预训练，预测未来 1/3/5 步的链长为 3.61/3.82/3.67，说明预测更远并不单调更好。作者还承认真机中“从头训但预测视频”不一定胜过完全无视频分支。

## 6. 成本、复现与跨视角启发

附录给出 12 层、12 heads、hidden 384；总参数 195M、可训练 46M。表3 预训练 batch1024、50 epochs、学习率 3.6e-4，CALVIN 微调 batch512、20 epochs、学习率1e-3；真机改 batch64、30 epochs。未给可核实 GPU 数、GPU-hours 或端到端延迟，不能自行换算显存与费用。

[官方仓库](https://github.com/bytedance/GR-1)公开 Apache-2.0 模型和 CALVIN 评测代码，并提供 ABCD→D、ABC→D checkpoint 链接；README 当前主要是评测流程，未提供完整 Ego4D 预训练和机器人微调流水线。权重链接存在不代表本次已下载验证；数据还需遵循 CALVIN/Ego4D 原许可。最具体的起步目标是复跑发布权重，再自行补训练实现，而不是宣称已具备原论文端到端复现条件。

GR-1 接收固定/腕部双视角，也监督两路未来图像，但没有跨相机对应、外参重投影或共享三维约束。共享注意力有机会融合互补信息，不能自动保证视角一致。对本项目可检验“同一动作状态下两路未来预测能否共享更一致的潜表示”；应把正常视角、移动相机、遮挡、缺失相机分开测。

与 Fast-WAM 相比，GR-1 展示的是小型 GPT 的视频预训练与并行查询头；没有 Fast-WAM 所研究的视频大模型动作生成/效率机制。两者可以共同支持“视频监督值得作为策略训练信号”，但各自是否测试时生成视频、如何计时、怎样解码动作都须分别核对。
