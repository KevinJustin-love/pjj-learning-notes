# π0 阅读笔记

核验日期：2026-09-25。论文：**π0: A Vision-Language-Action Flow Model for General Robot Control**，Physical Intelligence；固定阅读 [arXiv:2410.24164v4](https://arxiv.org/html/2410.24164v4)（2026-01-08；RSS 2025）。**状态：读过架构、训练与评测正文/附录，未复现。π0、π0-FAST、π0.5 是不同模型，下面只讨论 π0。**

## 它如何把 VLM 接到连续控制

π0 用 PaliGemma 视觉语言骨干理解图像和指令，再加入有独立权重的 action expert 生成连续动作。官方 openpi 仓库明确把 π0 列为 flow 模型，把 π0-FAST 列为自回归模型。[官方 openpi](https://github.com/Physical-Intelligence/openpi)

| 环节 | 固定版本论文配置 |
|---|---|
| 观测 | 2–3 张当前 RGB 图像、语言命令、本体状态（关节等） |
| 模型 | 约 3B 的 PaliGemma，加从头初始化的 300M action expert，总计约 3.3B |
| 动作 | 一次输出 50 步连续动作块，维度依机器人而定 |
| 训练 | conditional flow matching 的向量场 MSE |
| 推理 | 从高斯噪声出发，10 次 Euler 积分；缓存观测部分的 attention K/V |

令真实动作块为 `A`，噪声为 `ε`，构造 `Aτ = τA + (1−τ)ε`，训练 `vθ(Aτ, o, τ)` 逼近 `A−ε`。这是“学习如何把噪声搬到真实动作”的监督。论文中的 action token 指连续动作的序列槽位，**并不是 OpenVLA 的离散词表 token**。[论文 §IV、附录 A-B](https://arxiv.org/html/2410.24164v4#S4)

例如双臂 Trossen 配置使用两张腕部图像加一张外部图像，状态/动作空间为 14 维，一块即 `50×14` 个控制值。论文训练时把不同机器人的状态与动作补零到 18 维，并对缺失图像槽位加 mask；实际部署仍需按机器人的控制接口解码，不能直接把所有维度作为关节命令发送。[论文 §V-A、V-C](https://arxiv.org/html/2410.24164v4#S5)

## 训练数据与配方

预训练混合多种机器人、场景与任务，再用更精炼的任务数据做 post-training。论文 §V-A 报内部数据 **903M timesteps**、68 类任务；开源数据占训练混合的 9.1%，包含 OXE/Bridge/DROID。步数、轨迹数、小时数不是可直接互换的量。[论文 §V-A、图 4](https://arxiv.org/html/2410.24164v4#S5.SS1)

教学理解：多样演示提供“遇到各种情况怎样继续”的经验，后训练则让特定任务更稳定。但这不是强化学习：本论文动作目标来自演示，不能将 post-training 自动解读为 RL。小样本适配某任务的费用，也不包含得到预训练模型的费用。

## 评测口径与可核验结果

基础模型评测（§VI-A、图 7）包含五类任务，每任务/方法 **10 episodes**，使用归一化任务进度分数。附录 A-E 规定：bussing easy 按 7 个物体正确分类计分，bussing hard 按 12 个物体计分；这不是所有任务都“全成或全败”的成功率。基础模型的任务本身来自预训练分布，“无需后训练直接使用”不等于从未见过任务。[论文 §VI-A、附录 A-E](https://arxiv.org/html/2410.24164v4#S6.SS1)

原文报告 π0 在这些任务上高于比较方法；本文不从无数值标签的柱图猜造精确百分数。完整模型训练 700k steps；另有 160k-step 对照。作者也承认基线训练长度、参数量和预训练条件存在限制，所以不能把所有差异归结为 flow matching。[论文 §VI-A](https://arxiv.org/html/2410.24164v4#S6.SS1)

可以逐项核验的系统测量是**附录表 I：RTX 4090、三相机输入**：

| 阶段 | 延迟 |
|---|---:|
| 图像编码 | 14 ms |
| 观测前向 | 32 ms |
| 10 次动作 flow 前向 | 27 ms |
| 机载合计 | 73 ms |
| 加网络通信后的合计 | 86 ms |

其 50Hz 控制不表示整个 VLM 每秒调用 50 次。附录 A-D 说明，50Hz 机器人执行 25 步后重规划，20Hz 机器人执行 16 步后重规划；动作块内部为开环执行。[论文附录 A-D、表 I](https://arxiv.org/html/2410.24164v4#A1.SS4)

## 开放材料与实际成本

官方 openpi 提供基础与适配 checkpoint、训练/推理代码和例子，代码为 Apache-2.0。当前 README 的单 GPU 估计是推理 `>8GB`、LoRA 微调 `>22.5GB`、全量微调 `>70GB` 显存；测试系统为 Ubuntu 22.04，当前训练脚本不支持多节点。**这些是当前仓库使用估计，不是本文在本机测得的值。**[openpi Requirements](https://github.com/Physical-Intelligence/openpi#requirements)

当前仓库的公开 checkpoint 标注预训练于 10k+ 小时机器人数据。本文没有确认内部完整 903M-step 原始训练数据可下载，因此开放权重、能做下游微调与“可重做完整预训练”必须区分。具体权重使用条件还应读取对应 checkpoint 的说明，不能用代码许可替代。[openpi Model Checkpoints](https://github.com/Physical-Intelligence/openpi#model-checkpoints)

## 对跨视角一致性的意义：本项目分析

π0 的多相机条件是有价值的基线，但多视角输入本身不提供显式三维重建、跨相机重投影或未来画面一致性损失。论文输出是动作，不是未来多视角视频。因此，“π0 会使用多视角”与“π0 保证跨视角几何一致”是不同命题。

未来对照可逐一移除腕部/外部相机，或在保持物理状态与任务不变时改变外部相机位置。先保证时刻同步与动作坐标一致，再检查成功率和动作变化。若比较到 WAM，宜单独记录世界预测质量与控制成功率，避免仅凭视觉预测漂亮就推断动作更正确。以上均为待验证研究建议。
