# 从动作策略读到 VLA：四篇基础文献导引

核验日期：2026-09-25。本导引面向首次接触机器人学习的读者；论文事实链接到对应笔记和一手来源。**全部是文献阅读结果，已核对原文数字，但尚未运行 baseline、训练模型或独立实验验证论文结果。**

## 先理解三个对象

**观测 `o`** 是机器人在此刻能取得的信息，例如外部相机、腕部相机、关节位置。**语言 `l`** 说明目标，例如“把红杯子放进盘子”。**动作 `a`** 是交给控制器的数字，例如末端位置增量、关节目标或夹爪开合。看到“7 维动作”时，还要确认坐标系、旋转表示、单位与绝对/增量定义；维数相同不代表动作语义相同。

策略学习 `π(a | o, l)`：现在该做什么。世界模型学习动作后可能发生什么；WAM 的具体输入、输出和联合训练方式则应按各篇原文定义。是否用 diffusion/flow，不足以判断模型是策略还是世界模型：必须看它生成的是动作、视频、状态，还是其中多个。Diffusion Policy 和 π0 的扩散/flow 主输出都是动作，见各自方法部分。[Diffusion Policy §2](https://arxiv.org/html/2303.04137v5#S2)、[π0 §IV](https://arxiv.org/html/2410.24164v4#S4)

**模仿学习**用演示中的观测—动作对做监督。动作块 `A = [a_t, …, a_{t+H−1}]` 表示一次预测未来多步；执行其中几步后重新看相机，是滚动执行。长动作块减少模型调用并帮助保持动作连贯，也会推迟对新变化的反应。一个 50Hz 控制器可以执行预先预测的动作，并不要求模型每秒完整推理 50 次。

## 四篇文献分别教会什么

| 论文/阅读入口 | 核心问题 | 动作生成方式 | 读完应能解释 |
|---|---|---|---|
| [Diffusion Policy](related-work/diffusion-policy.md) | 多种合理动作与连贯的运动序列 | 连续动作块，条件去噪，噪声 MSE | 为什么一次生成一段动作；`To/Tp/Ta` 的区别 |
| [OpenVLA](related-work/openvla.md) | 如何把预训练 VLM 变成机器人策略 | 单步动作逐维分桶，自回归 token CE | 图像/语言怎样进入动作预测；量化和反归一化 |
| [π0](related-work/pi0.md) | VLM 语义如何支持高频、灵巧控制 | 连续动作块，action expert，flow MSE | 连续 token 与离散 token 的区别；推理/控制频率 |
| [FAST tokenizer](related-work/fast-tokenizer.md) | 高频动作逐步分桶的冗余 | DCT+量化+BPE，供 VLA 自回归预测 | tokenizer、策略两个训练层次；训练快≠推理快 |

以上分类来自各篇的架构/训练部分：[DP](https://arxiv.org/html/2303.04137v5#S2)、[OpenVLA](https://arxiv.org/html/2406.09246v3#S3)、[π0](https://arxiv.org/html/2410.24164v4#S4)、[FAST](https://arxiv.org/html/2501.09747v1#S5)。**FAST tokenizer 与 Fast-WAM 不是同一篇论文，也不是同一方法名称的缩写关系。**

## 两条动作路线的直觉

离散路线先把动作转成词表符号，模型像生成句子那样逐个预测符号，训练用交叉熵。OpenVLA 为每个动作维度分桶；FAST 将整个动作块压缩成较短符号串。符号越少，通常越少自回归步骤，但实际速度还由模型大小、硬件、缓存与解码实现决定。

连续路线不先把目标动作化为分类标签。Diffusion Policy 从噪声里逐次恢复动作；π0 学习连续向量场，将噪声逐步变成动作块。它们都可表达多种可行运动，并行更新一整个动作块。两条路线最终都必须输出控制器接受的连续数值，离散与连续指的是模型表示和训练方式。[DP 方法](https://arxiv.org/html/2303.04137v5#S2)、[OpenVLA 训练](https://arxiv.org/html/2406.09246v3#S3.SS2)、[FAST 算法](https://arxiv.org/html/2501.09747v1#S5)

教学例子：抓杯子可以从两侧接近。比较两个策略时，逐点动作 MSE 较小的策略未必更好；它可能平均了两种动作，或者只会模仿停顿。应在环境里执行，观察碰撞、抓取和任务完成。类似地，动作 token accuracy 高也不等于成功率高。

## 读数字时先填这张表

| 核对项 | 需要记录的内容 | 忽略后会造成什么误读 |
|---|---|---|
| 数据与阶段 | 从头训练、VLM 初始化、机器人预训练、目标任务微调 | 把更多数据带来的收益全归于架构 |
| 输入 | 单/多相机、历史、本体、语言；分辨率 | 将更多观测信息当成新损失的收益 |
| 输出 | 动作坐标、频率、块长度、执行步数 | 同维度却不同控制问题 |
| 任务分布 | 未见物体/环境/视角/机器人分别是哪一项 | 把一个维度的泛化当成全面零样本能力 |
| 指标 | 二元成功、部分进度、覆盖率、重建误差 | 把不同含义的百分比平均排名 |
| 统计 | 任务数、trials、种子、CI/标准误、checkpoint 选择 | 把最佳一次结果当作稳定收益 |
| 计算预算 | GPU 类型、时间、参数量、推理实现 | 把训练收敛快理解为部署延迟低 |

具体反例已经在笔记中标明：DP 的 Push-T 是覆盖率；π0 部分任务给进度分；OpenVLA 的 LIBERO 分 suite 训练，FAST 将四个 suite 合并训练。**没有共同协议，就不制作四者成功率排名。**[DP §5.2](https://arxiv.org/html/2303.04137v5#S5.SS2)、[π0 附录 A-E](https://arxiv.org/html/2410.24164v4#A1.SS5)、[OpenVLA 附录 E](https://arxiv.org/html/2406.09246v3#A5)、[FAST 附录 E](https://arxiv.org/html/2501.09747v1#A0.SS5)

## 与跨视角一致性课题怎样连接

以下是本项目的研究分析，不是四篇论文已验证的结论。

“同时看多台相机”“换相机仍能完成任务”“不同视角预测对应同一个物理场景”是三个不同要求。前者是输入设置，中间是视角泛化，最后才需要进一步定义一致性。仅把图像 token 拼接，不能自动证明最后一项。

对动作一致性，先将动作放入同一物理坐标系；对视频一致性，检查相机间物体身份、几何位置和运动是否对应。对多模态策略，两个不同动作样本都可能合理，不能未经分析就施加逐值相等；否则可能把真实的不确定性抹掉。

一个清楚的实验链条是：固定任务/数据/动作头 → 测试相机变化造成的退化 → 加入待研究的一致性机制 → 同时看任务成功率和一致性指标 → 检查收益是否仅来自额外视角或更多训练数据。世界预测指标与闭环控制指标应各自报告，最后再分析它们是否相关。

## 建议的学习顺序与可交付物

1. **DP：**画出“观测→动作块→执行前几步→新观测”的循环，写清三个 horizon。
2. **OpenVLA：**用一个假想 7 维动作说明归一化、分桶、token 预测和反归一化。无需下载 7B 权重就能理解这一步。
3. **π0：**对照上两篇画出 VLM 和 action expert，解释为什么 flow 的 token 不是词表索引。
4. **FAST：**手算“50Hz×14维=700 个逐维 token/秒”的表示成本，再解释 DCT/BPE 如何改变表示长度。
5. **转向 WAM：**逐篇列出生成目标，确认“世界预测”到底在哪个模块、由什么监督训练，再讨论跨视角约束的位置。

在复现之前，把这些阅读产物视为假设和协议设计。真正开始实验时，优先固定一个能获得数据、代码和评测环境的 baseline；完整预训练、下游微调、仅运行现成 checkpoint 应分别记录，不能共同写成“复现成功”。
